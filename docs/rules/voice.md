# Voice

Applies to marketing, docs/MDX, README, microcopy, error strings, comments, commits, and PRs.

- B2B-first dev brand. Audience: developers and PMs at Nigerian fintechs, bookkeeping SaaS, tax-prep startups.
- Period-separated short hits. Several 3-7 word sentences beat one long one: "PDF in, clean transactions out. Personal use. No signup. No storage."
- **No em-dashes anywhere.** Use periods, commas, parens, colons. Split an aside into two sentences. Date ranges use "to".
- Declarative. State what it does, then how. Active voice, concrete verb and noun, no hedging (might, perhaps, we think, potentially).
- No marketing words: seamless, powerful, robust, blazingly fast, intelligent, smart, AI-powered, agentic, supercharged, innovative, revolutionary, game-changer, effortless, world-class, industry-leading, 10x, leverage (verb), synergy.
- No apology theater ("we're sorry", "oops", "don't worry"). No "click here", no multiple "!".
- Honest privacy framing: "processed in memory, never written to disk". Never "we never see your data".
- "We" only for the team. Never "us / our customers" upsell-speak.
- No emojis in body copy. The one exception is the bank-coverage indicators (DESIGN.md).
- Errors follow `<what>. <why>. <do this>.` Never "Something went wrong."
- Lowercase bank names (palmpay, fbn, opay, zenith, matching `list_parsers()`) and `logickoder`. Bank names in plain text; logos only in the coverage grid.
- Naira amounts always in JetBrains Mono (visual rule).
- Links: brand or person credit ("Built by logickoder", footer name) → `https://logickoder.dev`. Code and repo links (engine, cloud, view source, self-host) → `github.com/logickoder/<repo>`.
